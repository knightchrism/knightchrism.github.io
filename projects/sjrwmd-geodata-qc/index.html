SJRWMD GeoData Quality Inspector

Rule-driven QA/QC for public groundwater-station GIS data: findings you can filter, inspect and export, with the source data left untouched.

Live dashboard Repository

Problem

Public GIS services are published as-is: records can be missing identifiers, geometry, or attributes that downstream users rely on. Fixing data you do not own is not an option, but documenting issues is. The goal: an automated, repeatable QA/QC workflow that pulls the public groundwater-station layer, applies configurable rules, writes every finding to an audit trail, and lets a reviewer explore them on a map.

Data sources

  • St. Johns River Water Management District public ArcGIS REST Feature Service: Active Groundwater Monitoring Network, Water Level Event Type
  • OpenStreetMap basemap for the dashboard

Key decisions

  • Rules as config, not code. All 8 rules live in config/qc_rules.json with id, field, check type, severity and an interpretation.
  • Raw download preserved. The original data is never modified.
  • Findings, not verdicts. Results are review findings, not confirmed errors.
  • Severity tiers: critical (identity, geometry), warning (county) and info (optional attributes).
  • Auditable outputs. Every finding is written to CSV/JSON; the dashboard filters by rule and severity and exports filtered CSV.
  • Static hosting on GitHub Pages, with no server to maintain.
